NEXORA AI — Nexora LeadFlow

Human-in-the-loop inbound B2B lead qualification for marketing agencies. FastAPI validates intake, SQLAlchemy stores leads and workflow events in PostgreSQL, an isolated OpenAI adapter returns strict structured analysis, and deterministic rules control classification and review routing. Response drafts are never sent automatically.

Run locally: copy .env.example to .env; keep `MOCK_AI=true` for no-credit development (no OpenAI key is needed); start PostgreSQL with `docker compose up -d db`; install requirements.txt; run `alembic upgrade head`; then `uvicorn app.main:app --reload`. Dashboard: http://localhost:8000. API docs: /docs. Health: /api/health.

Run full stack with docker compose up --build. Stop with docker compose down. Tests: pytest. Migrations: alembic upgrade head; after model changes create a revision with alembic revision --autogenerate -m "describe change", review it, then apply with alembic upgrade head.

Configuration: DATABASE_URL, OPENAI_API_KEY, OPENAI_MODEL, MOCK_AI, HUBSPOT_ENABLED, HUBSPOT_ACCESS_TOKEN, SLACK_ENABLED, SLACK_WEBHOOK_URL, RESEND_ENABLED, RESEND_API_KEY, RESEND_FROM_EMAIL, INTEGRATION_TIMEOUT_SECONDS, AI_CONFIDENCE_THRESHOLD, HIGH_VALUE_BUDGET_MONTHLY, CORS_ORIGINS, APP_ENV. Never commit .env. Without an OpenAI key the lead is saved and remains unclassified when MOCK_AI=false; the error/review event is logged.

## Development without API credits

Set `MOCK_AI=true` in `.env` to use deterministic local lead analysis without OpenAI requests or an API key. Mock mode follows the same schemas, qualification rules, persistence, event logging, response drafting, and human-review workflow as the live provider. Set `MOCK_AI=false` (the default) for production and provide a valid `OPENAI_API_KEY` and model configuration.

## Optional HubSpot and Slack integrations

Integrations are disabled by default. Enable `HUBSPOT_ENABLED=true` with `HUBSPOT_ACCESS_TOKEN` to upsert qualified leads to HubSpot, and/or `SLACK_ENABLED=true` with `SLACK_WEBHOOK_URL` to post qualified lead and human-review notifications. Calls use `INTEGRATION_TIMEOUT_SECONDS` (default 5 seconds). If an integration fails, lead intake and analysis remain successful; the workflow history records the failure. The health endpoint and dashboard show only provider modes, never credentials.

For local development, keep `MOCK_AI=true` and enable either integration. The matching mock adapter is selected automatically, requires no credentials, records mock workflow events, and sends no HTTP requests. With `MOCK_AI=false`, enabled integrations use their live adapters and require their credentials. Store real credentials in a local ignored `.env` or deployment secret manager; never commit them. Slack receives a concise lead summary and recommended action, not the full lead message or response draft.

## Human approved email

The workflow is lead intake → AI analysis → deterministic qualification → CRM sync → Slack alert → response draft → explicit human approval → email attempt → audit events. Drafts are never sent during lead creation, analysis, CRM sync, or Slack notification. In local mock mode (`MOCK_AI=true`), **Approve & Send** uses the local Mock Email provider and makes no network request. The dashboard labels this as Mock Email. Rejection and Request Information never send. A successful send is recorded per analysis draft, and repeat approval returns “already sent” rather than sending again. A failed attempt is recorded safely and can be retried.

For live Resend delivery, set `APP_ENV=production`, `MOCK_AI=false`, `RESEND_ENABLED=true`, `RESEND_API_KEY`, and `RESEND_FROM_EMAIL` using deployment secrets. Resend is disabled by default, and configuration status does not represent a connectivity check. In non-production with `MOCK_AI=false`, the email provider remains disabled. Email send failures return a safe error while preserving the human decision and workflow history.

Endpoints: POST /api/leads; GET /api/leads; GET /api/leads/{id}; POST /api/leads/{id}/reanalyze; POST /api/leads/{id}/approve (explicit approval and send); GET /api/dashboard/summary; GET /api/health; POST /api/leads/{id}/review. OpenAPI docs are generated by FastAPI.

The reviewer may approve, reject, request information, or reclassify a lead. Human decisions are recorded as workflow events. The example lead is Sarah Johnson at FinTechPro with fintech campaign needs, a stated monthly budget, and a 30-day launch horizon.

Before cloud deployment, configure managed PostgreSQL, platform secrets, TLS, allowed origins, production credentials, monitoring and backup policies. CRM, n8n, messaging, calendar and webhook integrations should be implemented as separate adapters. The included Compose credentials are local development values only.


## Windows PowerShell setup

From the workspace folder, after installing Python 3.11 or newer:

    py -3.11 -m venv .venv
    .\.venv\Scripts\Activate.ps1
    python -m pip install --upgrade pip
    pip install -r requirements.txt
    if (-not (Test-Path .env)) { Copy-Item .env.example .env }
    # Edit .env; keep DATABASE_URL pointed at localhost for local PostgreSQL
    docker compose up -d db
    alembic upgrade head
    uvicorn app.main:app --reload

Run the mocked test suite with pytest. Tests use an in-memory SQLite database and stub/mock all external providers; they do not call OpenAI, HubSpot, Slack, or Resend.
Seed the example after migrations with: python -m scripts.seed_demo. The seed is idempotent by its demo email address; set `MOCK_AI=true` for a no-credit analysis.
